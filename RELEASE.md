# 2.2.0 — Diagnostics and Pipeline

## Objective

Add structured diagnostics and complete Xml2Doc’s runner-based rendering pipeline so Core, CLI, and MSBuild provide deterministic, actionable CI behavior.

This milestone builds on the rendering extension points delivered in `2.1.0`.

## Included issues

- [ ] #39 — Structured diagnostics surfaced to CI
- [ ] #42 — Two-phase pipeline, parallel rendering, and incremental writes
- [ ] #44 — Expose remaining Core features through CLI flags and configuration

## Scope

### Structured diagnostics

- Define stable diagnostic identifiers, severity levels, messages, and source context.
- Introduce `IDiagnosticSink` or an equivalent diagnostic abstraction.
- Cover unresolved references, duplicate anchors, malformed XML, missing documentation, and other actionable conditions.
- Map Core warnings and errors appropriately into CLI output and MSBuild logging.
- Ensure warnings do not fail builds while errors produce non-zero CLI exit codes or MSBuild failures.

### Rendering pipeline

- Introduce an immutable symbol-index/build phase.
- Add a runner that coordinates planning, rendering, dry-run behavior, reporting, and output lifecycle operations.
- Support configurable parallel rendering of independent type pages.
- Preserve deterministic output ordering and byte-for-byte output across serial and parallel execution.
- Avoid rewriting files when the generated bytes have not changed.
- Report planned, written, skipped, and pruned files with useful timing information.

### CLI and configuration

- Expose the remaining applicable Core capabilities through CLI flags and JSON configuration.
- Complete structured diagnostic output after #39.
- Complete `--parallel` and runner-backed report/diff behavior after #42.
- Ensure external documentation fallback selects the required link policy.
- Add smoke and precedence tests for supported CLI/configuration options.
- Preserve existing defaults and compatibility.

## Recommended implementation order

1. #39 — Define the diagnostic contract.
2. #42 — Introduce the runner and two-phase rendering pipeline.
3. #44 — Complete CLI/configuration exposure using the finalized diagnostic and runner contracts.

## Completion criteria

- Core emits stable diagnostic identifiers with severity and relevant context.
- CLI and MSBuild display diagnostics appropriately for CI.
- Errors fail execution while warnings remain non-fatal.
- Serial and parallel rendering produce identical files.
- Repeated generation does not rewrite unchanged output.
- Reports distinguish planned, written, skipped, and pruned files.
- Dry-run, pruning, reports, and incremental generation operate through the same runner.
- CLI options override configuration-file values consistently.
- Invalid values produce actionable validation errors.
- Existing Core, CLI, and MSBuild defaults remain compatible with `2.1.0`.
- Documentation and migration guidance describe the new diagnostics and pipeline controls.
- All required tests and integration workflows pass on Windows, Linux, and macOS.
