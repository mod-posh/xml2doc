# Goals

Xml2Doc is designed around a small set of durable goals.

## Deterministic Markdown

Equivalent inputs and options must produce equivalent Markdown regardless of input order, supported target framework, operating system, or parallel rendering degree. LF is the default line-ending policy so generated bytes are stable across hosts.

For multi-project aggregation, primary XML inputs are canonicalized before loading and type/index ordering is stable and ordinal.

## One rendering contract across hosts

Core owns parsing, modeling, diagnostics, aggregation, and Markdown rendering. CLI and MSBuild translate host configuration into Core behavior rather than maintaining independent renderers.

Host-specific integration may differ where appropriate—for example CLI diff exit codes and MSBuild incremental targets—but Markdown semantics remain Core-owned.

## Safe output lifecycle

Xml2Doc should write only the outputs planned for the current invocation and delete only stale files explicitly owned by that invocation identity.

Incremental execution must regenerate missing outputs, react to relevant input/option changes, and avoid rewriting unchanged files.

## Stable diagnostics

Failures and warnings should use stable identifiers and consistent meanings across Core, CLI, and MSBuild. Hosts map those diagnostics to their native reporting surfaces without changing their semantics.

## Extensible rendering without default-output drift

Anchors, aliases, templates, auto-linking, external link resolution, signatures, and front matter are replaceable services. Built-in defaults remain deterministic and regression-tested.

## Explicit multi-project ownership

A repository-wide documentation set should have one aggregate owner. Multiple primary XML inputs are combined before rendering; independently generated indexes are not merged after the fact.
